## B3 — Ré-audit de sanitisation ⚠️ 4 fuites + 1 trou structurel

### Méthode

Deux volets, exerçant le **vrai chemin de production** (`sanitize_json_blob`, `sanitize_row`), pas
une réimplémentation :

1. **Blobs `eqLogic` / `cmd`** — pour chaque `eqType_name` présent, union des clés des colonnes
   `configuration` et `value_option`, puis confrontation de chaque clé aux trois mécanismes.
2. **Table `config`** — 359 lignes non-`core`. C'est là que vivent les identifiants de compte des
   plugins, et le premier volet l'aurait manqué.

Aucune valeur n'a été affichée à aucun moment : seulement le nom de la clé, le plugin, la longueur
et une classe de caractères (hex / base64ish / JWT / `crypt:` / texte).

### Ce que la regex (mécanisme 2) masque correctement

Sur les 359 lignes de `config`, **17 masquées** — et ce sont les bonnes :

```
cozytouch    password · atlantic_token · atlantic_token_expire
tesla        accessToken · refreshToken · tokenExpiresIn · tokenUpdatedAt
smartthings  access_token · refresh_token · client_secret · auth_code · token
mqtt2        mqtt::password      discordlink  Token      holmesMcp  token_2
```

Les comptes constructeur, les jetons OAuth et les mots de passe sont couverts **sans qu'aucune
entrée par plugin n'ait été nécessaire**. Les craintes formulées à l'ouverture de session sur
`tesla`, `smartthings` et `cozytouch` étaient donc infondées — c'est le résultat du contrôle, et
il valait d'être mesuré plutôt que supposé.

### 🔴 Le trou structurel — le mécanisme 3 ne s'applique pas à `config`

```python
def _sanitize_config_row(row):
    key_name = str(row.get('key', ''))
    if is_sensitive_key(key_name):      # ← pas d'argument `plugin`
```

`sanitize_row(table='config')` délègue à `_sanitize_config_row(row)`, qui appelle
`is_sensitive_key(key)` **sans passer le plugin**. Les extras par plugin — le mécanisme conçu
précisément pour rattraper ce que la regex rate — sont donc **inertes sur la table `config`**,
c'est-à-dire là où ils serviraient le plus.

Conséquence : le correctif jMQTT de J6-2 (`mqttUser` en camelCase) ne protège que les blobs
`eqLogic` / `cmd`. Ce n'est pas une liste à compléter, c'est **un argument manquant**.

### 🔴 Les 4 fuites confirmées

| Plugin | Clé | Forme | Cause |
|---|---|---|---|
| `geotrav` | `keyGMG`, `keyNavitia` | 39 et 36 car. | la regex porte `apikey`, `api_key`, `access_key`, `private_key` — **jamais `key` seul** |
| `tesla` | `jawglabKey` | 64 car. | idem, en suffixe |
| `mobile` | `api` | 32 car., **non chiffré** | `api` seul absent de la regex. Tous les autres plugins stockent `api` en `crypt:` — `mobile` est le seul en clair |
| `cozytouch` | `username` | 17 car. | son `password` est masqué, son login non. Demi-identifiant, même classe que le précédent jMQTT |

Ce sont des **clés d'API de services tiers en clair** qu'un client MCP recevrait aujourd'hui
telles quelles. C'est le résultat qui justifie que B3 ait été posé comme bloquant pour J8-5 : la
migration fait précisément transiter des données d'audit à travers ce sanitiseur.

### Ce qui n'en est pas — le tri compte autant que la trouvaille

Le premier passage heuristique signalait 32 clés résiduelles chez un plugin, 6 chez un autre.
Après tri, ce sont des **identifiants**, pas des secrets, et ils doivent rester visibles :
`serialNumber`, `entityId`, `roomId`, `deviceId`, `channelId`, `locationId`, `appId`, `client_id`,
`installed_app_id`, `installUUID`, `macad`, `deviceManufacturerCode`.

Et `autorefresh`, que le filtre signalait chez cinq plugins, est **une expression cron**.

Le filtre par forme (`base64ish` = alphanumérique ≥ 20 caractères) attrape tout texte sans espace :
noms d'icônes, chemins, topics MQTT. **Une heuristique de détection de secret produit
majoritairement des faux positifs, et le rapport doit livrer le tri, pas la liste brute.**

## Remédiation — deux chantiers distincts

1. **Passer le `plugin` à `_sanitize_config_row`** — mécanique, réactive le mécanisme 3 sur `config`.
2. **Découpage en mots dans le mécanisme 2** — `jawglabKey` → `jawglab` + `key`. Ajouter `key` et
   `api` en sous-chaîne attraperait `monkey`, `keyboard`, `rapide` : il faut segmenter les
   identifiants sur les frontières camelCase et `_`, puis tester chaque mot. Changement de nature
   du mécanisme, sur un module à **100 % de couverture obligatoire** (interdit dur n°9).
